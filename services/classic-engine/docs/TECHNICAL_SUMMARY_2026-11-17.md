# 技术方案与性能验证

2026-11-17。记录当前实现、正式对照及效果限制；图片、OCR 全文和实验中间产物保存在仓库外。

## 处理流程

```text
HTTP 接单 → 输入校验／文件拆页 → DBNet 检测与概率图合并
  → BallonsTranslator 分组 → classic／Hayai OCR → 取色、气泡、CTD 细化
  → 冻结分析 → 中心翻译与本地抹字并行 → Qt 排版
  → 无损差分覆盖／分块 → 持久化 → 交付确认
```

节点只负责图像与文件计算，LLM、账户和计费由中心处理。上游源码、模型、字体及许可通过固定版本与摘要交付；运行时只使用已校验资产。

## 当前实现

| 阶段 | 实现与约束 | 入口 |
| --- | --- | --- |
| 检测 | 保留短边尺度，超过检测尺寸才缩小；长边约为原窗口两倍，DBNet 两维补齐到 256 倍数。重叠保留原窗口的 1/5，整图概率图羽化合并后再提框 | `mtu_engine/upstream.lock.json` → 上游 `utils/generic.py`、`detection/default.py` |
| 检测后处理 | 像素阈值 0.5、框阈值 0.6、扩框 2.3；每等效窗口 1000 候选、最多 3000。uint8 二值图避免 int64 中间数组，跳过补边框、零面积框及空／分裂扩框 | `mtu_engine/engine.py`、上游 `detection/common.py`、`default_utils/dbnet_utils.py` |
| OCR／取色 | classic 按语言分流到 PP-OCRv5／Manga OCR；Hayai 使用原生有界批处理并拒绝截断输出。页面内复用裁剪与探测结果，灰度文字走快速取色，彩色代表行复用原生颜色头 | `mtu_engine/ocr/`、`colors.py` |
| 掩膜细化 | 直接调用固定 MTU CTD 主色／Otsu 及填洞；一次标记源连通域，逐行处理完整相交组件，保留大于 9 像素的门槛。RGB 转 BGR、annotation 模式、源笔画合并、字号相关膨胀、气泡约束与行间取消 | `mtu_engine/masks.py`、上游 `mask_refinement/__init__.py` |
| 抹字 | 纯色气泡先 CPU 填充，剩余区域交给 LaMa FP32。复用连通标签及内缩掩膜，保留原始修复边界和窗口顺序；AMD 可用启动期 HIP Graph | `mtu_engine/engine.py`、`inpainting.py` |
| 排版／输出 | 复用 MTU／Qt 原生测量、碰撞和绘制；每线程字形缓存最多 2048 项／65536 路径元素，每页可选参考掩膜缓存最多 64 MiB。无损 WebP method 4，长图排版后切块，编码借用空闲 CPU 预算 | `mtu_engine/layout.py`、`classic_node/render_pool.py`、`protocol.py` |
| 调度／恢复 | MPS 一次派发一个分析／抹字任务；下载、排版、交付独立并行。模型批次／块间取消；结果先持久化，未知交付保留冻结结果，确认终态才清理 | `classic_node/pipeline.py`、`runtime.py`、`document_runner.py`、`journal.py` |

检测输入逐批补边，预测裁剪后保存紧凑数组；批量受 `detect_batch_size × detect_size²` 像素预算约束，至少允许一张。长图 `930×28007` 从旧版 38 张 `1280×1280` 变为 13 张 `2560×1024`，累计模型输入像素减少 45.3%。单张前向更长，不能推导显存峰值或取消延迟必然下降。

细化仅支持节点使用的 `fit_text`，不再导入旧 CRF／填框模块；CUDA、AMD、Mac 环境均移除 `pydensecrf`。完整组件窗口避免检测多边形截断同一字形，源笔画恢复和气泡边界保护仍保留。切片、阈值及细化会改变识别与抹字像素。

## 31 张正式对照

**条件：** Apple M6 Mac mini，12 CPU／12 GPU 核、24 GB，PyTorch 2.14.1；Hayai MPS FP16、LaMa MPS FP32，GPU 回退关闭。检测批量 1、OCR 批量 8、CPU 线程 2、渲染进程 2、页面预算 2 GiB。

旧版为活动包 `648e964`，33 个 Python 文件、资产锁及字体配置已与提交核对；新版包含 MPS 调度、流式检测、长矩形、检测策略及 CTD 改动。两版使用相同输入、模型、字体和每区域相同的固定中文测试句。独立进程按旧／新／新／旧运行，每版两轮，每种输入尺寸先预热。

| 样本 | 页数 | 区域：旧 → 新 | 分析＋抹字＋排版输出：旧 → 新 |
| --- | ---: | ---: | ---: |
| 韩漫 | 6 | 5 → 5 | 1.509 → 1.503 秒 |
| 日漫 | 24 | 115 → 119 | 17.502 → 18.335 秒 |
| 长图 `930×28007` | 1 | 30 → 38 | 12.478 → 9.886 秒 |
| 合计 | 31 | 150 → 162 | 31.489 → 29.723 秒 |

长图阶段均值：分析 **8.631 → 5.404 秒**，抹字 **2.320 → 3.388 秒**，排版输出 **1.524 → 1.091 秒**。新增召回增加后续工作，不能只用检测或细化耗时代表整页收益。

真实本地调度的 31 任务流水线，两轮均值 **29.418 → 28.555 秒**，约减少 2.9%；仅两轮不足以证明稳定吞吐提升。每轮 31 个任务全部完成，交付日志清空，输出与逐页运行一致；各版两轮的分析、抹字像素、排版像素及输出摘要稳定。中心和网络为本地模拟，固定句不是实际翻译。

流水线 RSS 求和峰值范围：旧版 **6.266–6.623 GiB**，新版 **5.405–6.067 GiB**；逻辑预留峰值 **1250.5 → 971.8 MiB**。RSS 可能重复计入共享页，逻辑数组、局部分配、RSS 与设备分配不能相加。

### 已确认的画质问题

- 日漫第 2 页：旧版保留完整主标题，新版只抹除一部分；新增识别未形成完整处理。
- 日漫第 6 页：两版均有注音残留，位置和形态不同。
- 日漫第 15 页：同一句固定长中文在两版均发生竖排跨格。
- 韩漫第 2 页：原图页边截断文字在两版均保留。
- 长图全部旧 30 区域匹配，28 处规范化 OCR 一致，新增 8 区域；日漫第 17 页有分组／匹配变化，第 18 页有一处匹配 OCR 变化。未匹配区域不自动等于漏检。

这些问题尚未修复；运行通过及重复输出稳定不代表画质验收。区域数增加也不等于准确率提高。

本机证据在桌面 `漫画对比网站-20261117/`：`comparison.json` 汇总指标，`metrics/` 保留四轮原始测量，`provenance.json` 和各轮报告记录版本及源码摘要。网页仅在回环地址提供图片与 OCR。长图 SHA-256：`701f0f31ac43a53af300730e4de3840e5f6355f07b3c00b952304009565cea51`。

## 独立实验的有效结论

下表来自各自同条件对照，区域数、译文及运行方式与上述整集测试不同，耗时和百分比不能拼接或相加。

| 改动 | 同轮对照：旧 → 新 | 结论 |
| --- | --- | --- |
| MPS 调度／CPU 预算 | 首张交付 23.60 → 13.76 秒；四任务 50.08 → 50.95 秒 | 改善首张延迟，未证明吞吐提升 |
| 空闲 CPU 并行输出 | 中文排版输出 1.428 → 0.833 秒；编码封包 0.912 → 0.301 秒 | 输出字节一致；累计 CPU 时间增加约 8.6%，不代表节能 |
| 流式输入／紧凑预测 | 补边数组存活峰值 178.125 → 9.375 MiB；预测底层数组 534.375 → 282.093 MiB | 缓冲减少；正式分析／四任务耗时差仅约 1.1%／0.4% |
| uint8 DB 后处理 | 可追踪分配峰值 248.4 → 49.8 MiB | 有效框与评分等价，属于局部分配改善 |
| CTD，同样 38 区域、框阈值 0.6 | 细化 3.806 → 0.222 秒；分析 9.015 → 5.496 秒；四任务 52.323 → 37.430 秒 | OCR、几何、取色、原始掩膜和气泡一致，修复像素会变；RSS 未下降 |

CTD 独立实验逐项查看了长图 38 处裁剪，各版自身掩膜外原图像素不变；该结论不覆盖整集新发现的标题问题。长矩形检测取消在首批后约 0.293 秒响应，CTD 首行后约 1.7 毫秒；均为指定触发点，不是最坏延迟。

## 验证与交付

- CPU／上游组件回归覆盖补丁精确应用及漂移拒绝、尺度与接缝、横竖还原、候选上限、输入批量及预测所有权、无效框、完整字形、气泡边界、取消与恢复。
- 真实 MPS 接缝回归：恰好 256px 重叠，横竖长图、18px／26px 共 90 行，检测与经典英文 OCR 完整，无重复，细化覆盖字形及抗锯齿边缘。执行命令见[引擎 README](../README.md)。
- Windows 包、Linux 镜像／在线安装和 Mac 共用 `tools.prepare_mtu`；新 `masks.py` 随现有源码目录交付。升级需按新锁重新准备资产与依赖，旧资产清单会被拒绝；按[恢复规则](NODE_OPERATIONS.md)排空并保留私有配置及未确认结果。
- 本轮仅交付源码、锁文件和文档，测试后本地节点恢复旧包。其他 GPU、Linux 实机、真实中心端到端、大规模人工准确率及持续功耗未验证。
